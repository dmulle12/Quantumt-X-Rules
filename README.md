Quantumt-X-Rules

Automatically generated Quantumult X rule sets based on Loyalsoldier’s rule sources.

This repository converts upstream domain and IP lists into Quantumult X-compatible filter rules and updates them automatically using GitHub Actions.

Features

* Quantumult X compatible rule format
* Automatically updated from upstream rule sources
* GitHub Actions powered
* Separate rule sets for Proxy, Direct, Reject, China IP, Telegram IP, and more
* Rules are published through the release branch
* Suitable for use with Quantumult X [filter_remote]

Quantumult X Usage

Add the desired remote rules to your Quantumult X configuration:

[filter_remote]
https://raw.githubusercontent.com/dmulle12/Quantumt-X-Rules/release/ruleset/reject.txt, tag=Reject, force-policy=REJECT, update-interval=172800
https://raw.githubusercontent.com/dmulle12/Quantumt-X-Rules/release/ruleset/proxy.txt, tag=Proxy, force-policy=PROXY, update-interval=172800
https://raw.githubusercontent.com/dmulle12/Quantumt-X-Rules/release/ruleset/direct.txt, tag=Direct, force-policy=DIRECT, update-interval=172800
https://raw.githubusercontent.com/dmulle12/Quantumt-X-Rules/release/ruleset/cncidr.txt, tag=China-IP, force-policy=DIRECT, update-interval=172800
https://raw.githubusercontent.com/dmulle12/Quantumt-X-Rules/release/ruleset/telegramcidr.txt, tag=Telegram-IP, force-policy=PROXY, update-interval=172800

Make sure PROXY, DIRECT, and REJECT match the policy names configured in your Quantumult X profile.

Rule Format

The generated rules use Quantumult X syntax.

Examples:

HOST,example.com,PROXY
HOST-SUFFIX,example.com,PROXY
HOST-KEYWORD,example,PROXY
IP-CIDR,1.2.3.0/24,PROXY
IP-CIDR6,2001:db8::/32,PROXY

Common Surge-style rules are converted to their Quantumult X equivalents where applicable:

DOMAIN          → HOST
DOMAIN-SUFFIX   → HOST-SUFFIX
DOMAIN-KEYWORD  → HOST-KEYWORD
IP-CIDR         → IP-CIDR
IP-CIDR6        → IP-CIDR6

Automatic Updates

The rule sets are generated by GitHub Actions.

The workflow:

1. Downloads the latest upstream rule data.
2. Converts the data into Quantumult X-compatible syntax.
3. Cleans and sorts the generated rules.
4. Publishes the generated files.
5. Updates the release branch.
6. Purges jsDelivr cache for the updated rule files.

Quantumult X can then periodically fetch the remote rules according to the configured update-interval.

Data Sources

This project uses publicly available rule data from:

* Loyalsoldier/domain-list-custom
* Loyalsoldier/v2ray-rules-dat
* Loyalsoldier/geoip
* felixonmars/dnsmasq-china-list

The upstream projects remain the original sources of the underlying rule data.
